# 踩坑清单（按重要性排序）

这些是实际做这部片时踩出来、且**不写下来必然重踩**的点。改动引擎前先读一遍。

1. **逐帧随机颗粒会摧毁 H.264 编码。** 如果每帧都换一张随机颗粒，1080p 单帧编码会从 ~25ms 暴涨到 ~3500ms。解决：全片复用**同一张**静态颗粒版（本引擎 `grain_plate` 已按此实现）。想加"动"的颗粒，用位移/透明度变化，不要每帧重新随机。
2. **所有动效的时间必须统一"按秒"。** 曾经因为粒子/字幕拿"帧序号"和"秒"混用，导致字幕**完全不显示**（条件永远不成立）。引擎里 `compose(scene, t)` 内部一律用 `ts = t/fps`。
3. **长渲染必须前台同步跑。** 某些沙箱里 `nohup`/后台进程会在发起它的命令结束后被**挂起**（CPU≈0、进度停滞）。要么前台跑，要么交给能前台值守的子进程/子 Agent。
4. **沙箱 CPU 常是突发配额型。** 空闲时 1080p x264 约 25~30ms/帧，连续跑重活会被限流到 1~3s/帧。同一操作不同时间能差上百倍——**别把限流当成死循环**。
5. **用 rawvideo 直灌 ffmpeg，不要逐帧存 PNG。** PNG 编码是主要瓶颈。引擎把每帧 `img.tobytes()` 直接 `stdin.write` 给 ffmpeg。
6. **`cv2.remap` 对单通道要 reshape。** `(H,W,1)` 会报 broadcast 错；引擎用 `warp_chan()` 把单通道 `[...,None]` 再取回。
7. **上色时长占比过低会退回"整盆泼"。** 建议占比 50~60%（很多镜头实际用了 4~6.5 秒），太快就看不出是"画"出来的。
8. **字体要下全。** 下载被截断时 PIL 仍能 load 但**缺字**。缺字体时 `load_font` 会回退到系统 Noto Serif CJK。
9. **`pkill -f "关键词"` 会匹配到执行它的 shell 自身而自杀。** 用 `[关]键词` 写法或按 PID 精确杀。
10. **底图非 16:9** 时引擎用 `fit_cover` 居中裁剪；若想看到全图，先自己把底图做成目标比例。
11. **字幕压在深色画面上会看不见。** 用浅色字 + 深色描边（引擎默认 `color=(246,241,230)`、`stroke_width=3`）。
12. **可复现性**：固定 `seed`；素材（底图）若由生图模型产生则**不可复现**——那一步要在流程外固化（保存最终图）。
